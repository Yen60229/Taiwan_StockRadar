# 07 · 股價淨值比（PB）評價

> 2026-11-07 第一階段完成 · 2026-11-10 第二階段完成
> 參考：BOS 巴菲特線上學院〈股價淨值比是什麼？多少算便宜要看產業〉
> <https://buffettonlineschool.com.tw/price-to-book/>

## 要做什麼

1. 篩選結果顯示每檔的 **PB** 和 **每股淨值**。
2. 每檔給 **便宜／普通／昂貴** 評級。
3. 點產業可以看 **同產業所有股票的 PB 排名**。

## 文章重點

- PB = 股價 ÷ 每股淨值。
- 「PB 低於 1 就便宜」不能套用到每個產業：半導體中位數 3.17，塑膠 0.78。
- 要跟同產業比，也要跟公司自己的歷史比。
- 產業排名順序穩定，但數字每年都在變，不能寫死門檻。
- 不到 10 家的產業，樣本太少，不拿來比。
- 淨值為負時 PB 沒有意義，證交所會留空。
- PB 低常常是因為公司不太賺錢，要一起看有沒有虧損。

## 評級規則

在 **同產業（上市＋上櫃）** 裡排名：

| 評級 | 條件 |
|---|---|
| 便宜 | 排在最低的 25% |
| 普通 | 中間 |
| 昂貴 | 排在最高的 25% |
| 不評級 | PB 空白，或同產業不到 10 檔 |

另外加兩個小標籤（不影響評級）：

- **低於淨值**：PB < 1
- **虧損中**：本益比空白

門檻 25%、75%、10 檔都放在同一個地方，要調整只改一處。

## 資料來源

用交易所每天公布的「本益比、殖利率、股價淨值比」表（2026-11-07 已實測）：

| | 上市 | 上櫃 |
|---|---|---|
| 網址 | `www.twse.com.tw/rwd/zh/afterTrading/BWIBBU_d?date=20261106&selectType=ALL&response=json` | `www.tpex.org.tw/www/zh-tw/afterTrading/peQryDate?date=2026/11/06&response=json` |
| 欄位 | 證券代號、證券名稱、收盤價、殖利率、股利年度、本益比、股價淨值比、財報年/季 | 股票代號、公司名稱、本益比、每股股利、股利年度、殖利率、股價淨值比、財報年/季 |
| 筆數 | 1,087 | 891 |
| 本益比空白 | `-`（209 筆） | `N/A`（217 筆） |
| 季別原始寫法 | `115/2` | `115Q2` |
| 有收盤價 | 有 | 沒有，改用 `daily_quotes` 同一天的收盤價 |

好處：

- 每個市場每天只要抓一次，放進現有的每日排程。
- 可以指定日期，第二階段抓歷史也用同一個網址。
- 本益比、殖利率順便存下來，以後用得到。

注意：

- 財報公告期間，各公司的季別會不一樣。11/6 實測約 2 成已換成 Q3，其餘還是 Q2。畫面上要顯示每檔的季別。
- 兩邊格式統一後才存：數字去逗號、本益比空白（`-`、`N/A`）都存成空值、季別統一成 `115/Q2`。

每股淨值 = 收盤價 ÷ PB。PB 只到小數兩位，淨值會有約 0.5% 以內的誤差，畫面上會註明。

## 資料表

新增 `valuations`：

| 欄位 | 說明 |
|---|---|
| `stock_code`、`trade_date` | 兩個一起不可重複 |
| `pb_ratio` | 股價淨值比，可空白 |
| `pe_ratio` | 本益比，可空白 |
| `dividend_yield` | 殖利率 % |
| `bvps` | 每股淨值 |
| `fin_period` | 財報季別，例如 `115/Q2` |

評級不存進資料庫，每次查詢時用當天資料算。

## 後端

- 兩個爬蟲各加一個函式，抓指定交易日的估值表。
- 每日排程抓完行情後，順便抓估值，寫進 `valuations`。
- 排名用一段 SQL 算完（約 1,900 檔，資料庫排序一次就好）。
- 篩選 API 另外查估值再用代號合併，不把排名 JOIN 進篩選的大查詢：實測 JOIN 進去會從 27 ms 變成 355 ms，分開查約 53 ms。
- 評級寫成一個獨立函式 `rate_pb()`，方便測試。

API：

| 端點 | 內容 |
|---|---|
| `GET /api/screen` | 每檔多帶 PB、淨值、本益比、評級、產業排名；可只篩某幾種評級 |
| `GET /api/valuation/industry` | 新增。回傳某產業所有股票的 PB 排名、中位數、最低、最高、檔數 |
| `GET /api/stocks/{code}` | 多帶 PB、淨值、評級 |

## 前端

- 表格加三欄：PB、每股淨值、評級。
- 評級顏色：便宜綠、普通灰、昂貴橘（不用紅色，台股紅色是漲）。
- 篩選列可勾選只看某幾種評級。
- 點產業標籤開側邊面板：
  - 同產業 PB 由低到高的橫條圖，標出中位數
  - 顯示最低、最高、檔數
  - 可切換「全市場同產業」或「只看篩選結果」
  - 底部提醒：PB 低不代表該買，要看獲利
- CSV 匯出多加 PB、淨值、本益比、評級。

## 測試

- 爬蟲：用真實回應存成範例檔測試，PB 空白要變成空值。
- `rate_pb()`：測 25%、75%、9 檔、10 檔、空白等邊界。
- API：檢查新欄位和新端點。
- 資料表：檢查 migration 和程式一致。

## 第二階段：跟自己的歷史比

文章說要「跟同產業、也跟這家公司自己的歷史一起看」。第一階段做了同產業，這一階段補上自己的歷史。

### 評級規則

取這檔過去 5 年每個月最後一筆 PB（不含本月），看目前 PB 排在哪：

| 評級 | 條件 |
|---|---|
| 便宜 | 排在自己歷史最低的 25% |
| 普通 | 中間 |
| 昂貴 | 排在自己歷史最高的 25% |
| 不評級 | PB 空白，或歷史不到 36 個月（3 年） |

- 排名用「比目前低的月數 + 相等月數的一半」÷ 總月數，PB 長期持平時不會被判成極端。
- 畫面上兩個評級並列。兩者一致時可信度較高；不一致時（例如同產業便宜、自己歷史昂貴）要再看獲利與現金流。

### 參考價位

便宜價／合理價／昂貴價 = 目前每股淨值 × 自己歷史 PB 的第 25／50／75 百分位。
這組價位是本專案自訂，文章沒有提出。淨值變動後價位會跟著變。
歷史不到 36 個月不提供，跟評級同一個門檻，避免幾個月的資料算出誤導的價位。

### 歷史資料

- 新增 `scripts/backfill_valuation.py`，上線後執行一次，補過去 5 年每個月最後一個交易日。
- 每月只取一天：約 120 次請求（逐日要 2,400 次）。
- 證交所遇到假日會回 307 轉址到「因為安全性考量…」頁面，跟限流時一樣分不出來。
  櫃買中心假日會清楚回 0 筆，所以先用櫃買中心找出交易日，再拿同一天去問證交所。
- 證交所請求間隔 6 秒。被封鎖時同一天冷卻 2、4、8 分鐘再試；連續 2 個月冷卻完仍被擋，
  這次就只補上櫃，結尾提醒稍後重跑（重跑只補缺的月份）。
  開發環境實測：封鎖時間跟請求頻率對不上，研判是共用對外 IP 被擋；正式主機有自己的 IP，你在本機實測時證交所也都正常。
- 寫入用 `keep_existing`，不會把每日排程算好的每股淨值蓋掉。
- 已經回補過的月份會跳過，可以重複執行；某個月上市被限流沒抓到，重跑就會補上。
- 每日排程的列和回補的月底列都寫進 `valuations`，同時更新每月快照表 `valuation_monthly`
  （每檔每月一筆，該月最新一天的 PB）。歷史計算只讀快照表：每檔最多 60 筆，
  不會因為 `valuations` 每天多 2,000 筆而越查越慢。
- migration 建表時會從現有的 `valuations` 補出快照。

### API 與畫面

| 項目 | 內容 |
|---|---|
| `GET /api/screen`、`/api/stocks/{code}`、`/api/valuation/industry` | 多帶自身歷史評級、歷史百分位、月數、參考價位 |
| `GET /api/valuation/history/{code}` | 新增。過去 5 年每月一點的 PB，加上第 25／50／75 百分位 |
| 篩選表格 | 多一欄「評級・自身歷史」，篩選列多一組自身歷史評級，CSV 多四欄 |
| 同產業面板 | 明細表多一欄自身歷史評級 |
| 個股頁 | PB 走勢圖（標出低檔、中位數、高檔）與便宜價／合理價／昂貴價 |

### 效能（480 檔篩選結果，本機實測）

| 查詢 | 時間 |
|---|---|
| 同產業排名 | 約 40 ms |
| 自身歷史 | 約 22 ms |
| 篩選 API 合計 | 約 100 ms |

兩段都只讀「最近 10 天的估值」與「每檔 60 筆月快照」，資料累積幾年也不會變慢。

### 上線步驟

1. `bash scripts/deploy.sh`（會建 `valuation_monthly` 並從現有資料補出快照）
2. `docker compose -f docker-compose.prod.yml exec scheduler python scripts/backfill_valuation.py`（約 5～10 分鐘）
3. 結尾若提醒有月份沒抓到上市資料，過一段時間再跑一次第 2 步

## 實作時多做的事

- 證交所請求太密時會斷線或回 307（限流）。估值表和三大法人都加上重試，同一個交易所的請求依序送出，兩個交易所之間才並行。
- `docs/deploy-to-vps.md` 的更新指令改成 `deploy.sh`，原本的寫法會跳過 migration。
